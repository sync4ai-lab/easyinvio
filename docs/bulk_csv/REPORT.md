# CSV orders v2 — implementation and verification

The standard download now contains exactly the requested 21 columns, in order:

```csv
order_reference,cargo_type,origin_name,origin_line1,origin_city,origin_postal_code,origin_country_code,recipient_name,recipient_phone,destination_name,destination_line1,destination_city,destination_postal_code,destination_country_code,length_cm,width_cm,height_cm,weight_kg,currency,item_description,item_declared_value
```

The download is generated by `/api/v1/shipments/batch-template`, the same schema
used by the importer. It contains replaceable domestic parcel, letter, pallet
and UK–US examples. Reference files are also stored in `templates/orders.csv`
and `templates/orders_extended.csv`. Existing 16-column files remain accepted;
international legacy rows now stop for missing customs data instead of sending
an incomplete carrier payload.

## Where values go

| CSV fields | Persisted/application behavior |
|---|---|
| order_reference | Shipment customer reference; stable tenant-scoped import identity unless an explicit idempotency UUID is supplied. |
| cargo_type | LETTER, PARCEL, PALLET or OVERLAND_FREIGHT; persisted to shipment and passed into the shared rating engine. |
| origin_* | Sender address and origin country. |
| recipient_name / destination_name | Recipient contact name; destination name is retained as company/site when different. Blank recipient_name falls back to destination_name. |
| recipient_phone | E.164 recipient phone in the address, carrier request and saved order. |
| destination_* | Recipient address/destination country; optional state/province is available in the extended template and review form. |
| length/width/height and weight_kg | Packed dimensions and actual gross kg, saved to shipment. Shared Decimal calculations derive express or freight billable weight. |
| currency | Shipment, quote and declared goods currency; no exchange rate is guessed. |
| item_description / item_declared_value | Saved order/customs draft and HS suggestion. Declared value is **per unit**, not the shipping price. On review, complete goods rows populate customs_items and the carrier customs request. Default quantity is one. |

Domestic valid rows are saved and quoted independently, with all returned carrier
options retained. Imported rows appear in Manifest. Quotes use the same automation,
margin and carrier services as individually prepared orders. CSV processing shares
the existing bounded order semaphore rather than launching 1,000 provider calls.
Upload and review use QUOTE_ONLY: no carrier purchase, wallet debit, printer
broadcast or real marketplace fulfillment occurs.

Unchanged re-uploads reuse the stored shipment. Changed data under an existing
reference/idempotency key returns a row conflict rather than silently overwriting
an order. Duplicate references or invalid rows do not prevent valid peers from
processing. Valid orders whose carrier/rating service fails remain saved, and the
existing automation failure-ticket path records the issue where available.

## International review and extended columns

These 21 columns capture the requested data but cannot establish a product's
manufacturing origin, net weight, reviewed HS classification or signer. Such
international orders are saved as PENDING_IMPORT with a draft declaration and a
`customs_review_required` result. No carrier request is sent while these facts
are missing. Warehouse country is never substituted for goods origin and gross
packed weight is never silently treated as goods net weight.

Click **Review customs & quote** in the results, or **Review uploaded customs**
on the saved manifest row. The dialog pre-fills the description, value, contact
and HS suggestion while leaving unknown origin/net weight blank and the review
checkbox unchecked. Supply actual goods facts, recipient state/province where
needed, an explicit HS code and signer, and confirm review. The backend validates
net × quantity ≤ gross weight, persists the reviewed declaration/reviewer, and
passes the document into carrier rating before any immutable shipment is created.
CN22/CN23 can be selected; operator eligibility still requires verification.

The optional extended template contains:

```text
stackable, origin_state, destination_state, item_quantity, item_origin_country,
item_net_weight_kg, hs_code, hs_codes_reviewed, customs_signer, postal_form,
incoterm, sender_eori, recipient_eori, sender_vat, recipient_vat, store_id,
store_order_id, platform, idempotency_key
```

`item_net_weight_kg` is per-unit net kg; `item_declared_value` is per-unit declared
value. Quantity defaults to one. LETTER ignores box measurements and must weigh
strictly below 0.5 kg. Pallet/road-freight rows default to non-stackable unless
`stackable=true` is explicitly supplied. Existing configured freight factors apply.
Phone numbers use `+` and country code. Excel-safe downloads prefix the phone with
an apostrophe; the importer removes only that valid E.164 text prefix.

For marketplace association, supply **store_id, store_order_id and platform**
(SHOPIFY/WOOCOMMERCE/AMAZON). The registered active store must belong to the
authenticated tenant and match the platform. Use the real API order ID, not merely
the displayed order reference. Uploaded associations are retained so the existing
confirmed-label settlement hook can create the tracking push-back event later.
The standard layout does not invent these IDs or infer a store from a customer name.
Live remote delivery still depends on the previously documented provider adapters
and credentials. It is not triggered by a quote.

## Database and checks

**No new migration is required in the currently configured sandbox.** Migration
016 already permits PENDING_IMPORT without an invented carrier. Once an order is
quoted, the existing carrier, packing, customs and financial constraints apply.
All tenant identity comes from server authentication; CSV tenant_id columns are
rejected. Accountants cannot import or review; warehouse dispatchers can operate
on their own orders but do not receive wholesale/platform markup fee components.

Verification passed:

- 97 relevant backend/security/regression tests, including ten new CSV tests.
- Real Supabase save/quote checks for parcel, letter and pallet; replay/changed-data
  checks; staged UK–US import followed by reviewed customs persistence and carrier
  payload checks; cross-tenant review rejection; store identity/tracking outbox handoff.
  Carrier responses were controlled and **every test database write rolled back**.
- Actual browser download → upload → review → quote → export, including the 21-field
  standard and extended template. No JavaScript errors; no page overflow at
  375/768/1366 widths. Preview operations made zero database writes.
- Existing owner controls, role-based navigation, cargo/customs/manifest flows and
  mobile layout checks. The configured backend was restarted and its health and
  21-column template endpoints returned HTTP 200.

Detailed local receipts are `database_evidence.json` and `browser_evidence.json`.
They are environment-specific artifacts excluded from Git; test scripts and this
report are committed.
